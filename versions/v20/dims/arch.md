# G0 架构对标（通用，首跑）

隔离与对标**能力组件层**：这个系统由哪些部分构成、缺哪个、哪个多余、底层组件该不该换。

不判文件怎么放（G5）、不判数据怎么流（A1）、不判代码怎么写（G1–G7）。

**本文件不含任何领域清单。** 该领域的共识构成每次现搜，流程见 `refs/standard.md`。

---

## 一、为什么最先跑

架构层缺件时，下层评审失去意义。缺状态持久化，拆文件解决不了"任务中断要重跑"；缺审批点，补按钮解决不了"高危动作无人确认"。

先出能力矩阵，再决定下面各维要不要跑、跑哪几维。

---

## 二、怎么拿到该领域的共识构成

三步，每步都写进报告第 2 节：

1. **搜**：`<对象类型> architecture components <年份>`、`<对象类型> reference architecture`、`<对象类型> 源码研究`。
   找有"子系统 × 最小形态 × 成熟形态"这类对照的材料，或官方参考架构。
2. **验**：按 `refs/standard.md` 四问——一类事吗、规模差几级、有实现细节吗、能追到结果吗。
3. **落**：把这次采样的构成表写进报告，标来源与日期；**不写进技能本体**。

`refs/samples/` 里有历史采样可作格式参考，但不可直接当本轮标准。

---

## 三、逐项判定四档

对搜到的每个子系统：

| 档 | 判据 | 记法 |
|---|---|---|
| **有** | 找到实现且能指出入口 | ✅ |
| **部分** | 有雏形但覆盖不全，能说出缺哪一段 | ◐ |
| **无** | 反向词表搜过仍无实现 | ✗ |
| **不需要** | 能写出"缺了会怎样"且能说明这套场景下为何不成立 | — |

**"不需要"必须写两句**：缺了会发生什么、为什么这里不成立。少一句就退回"无"。

例：只读工具型系统不必要独立沙盒，因为它不执行自己生成的代码——**前提是没有代码执行入口**，有了前提就变。

---

## 四、底层组件该不该换

对象依赖了某个框架、内核、中间件、运行时。判"该换"还是"保守"：

1. 从上面搜到的共识里，取**该领域公认的判定角度**（不同领域角度不同：有的看能力覆盖，有的看维护活跃度，有的看迁移成本）。
2. 逐角度判"落后 / 持平 / 领先"。
3. **门槛**：落后项 ≥ 全部角度的三分之一，且每项都能追到结果影响（等太久 / 会做错 / 不敢信 / 找不到），才写"建议更换"。
4. 不足门槛 → 记"保守"，进权衡点，不算缺陷。

**不推荐具体替代品**——选型是决策者的活。

---

## 五、防误报（本维误报率最高）

架构能力最容易被**命名**误导。断言"没有 X"之前，必须搜过反义与替代实现：

| 断言 | 必搜 |
|---|---|
| 无记忆 | memory / history / context / compact / summarize / session / 长期存储 |
| 无持久化 | resume / checkpoint / durable / recover / restore / 续跑 |
| 无沙盒 | container / isolation / jail / workspace / mount / 进程启动方式 |
| 无可观测 | trace / span / log / metric / telemetry / token 计量 |
| 无审批 | approval / confirm / interrupt / human-in-the-loop / 权限分级 |
| 无编排 | subagent / task / spawn / queue / 并发上限 |

**依赖包也是实现**。能力可能来自 npm / pip 依赖（如某 `*-durable` 包提供持久化），不在源码里。判定前先读 `package.json` / `requirements.txt`，把依赖算进"有"。

**目录名不等于能力**。一个叫 `engine/xxx/` 的目录可能只是自建工具集，真正的东西在依赖里。

## 六、输出形态

```
## 共识构成（本轮检索）
| # | 子系统 | 来源 | 年份 |

## 能力矩阵
| # | 子系统 | 现状 | 成熟形态 | 差距 | 结果类 | 判定 |

## 三条结论
1. 缺什么（按结果影响排序，不按清单顺序）
2. 什么可以不要（给理由与前提）
3. 底层组件该不该换（够门槛才写"建议更换"）

## 前置前提
这套判定成立的前提：允许执行生成代码 / 需要跨会话续跑 / 有多任务并发。
前提不成立时，对应项从"缺"降为"不需要"。
```

---

## 七、与其它维的边界

| 维 | 判的是 | 例 |
|---|---|---|
| **G0** | 有哪些部分、缺哪个 | 缺人工审批点 |
| G5 结构 | 文件与模块怎么放 | store 文件 2078 行 |
| A1 数据流 | 数据怎么流、层间依赖 | engine 直接 import 上层 |
| G3 可靠 | 运行时行为 | 并发满直接拒绝 |

同一件事只能落在一条维里。G0 说"缺持久化"、G5 说"store 太大"是两件事；若 G5 的结论其实是持久化缺失导致的，写到 G0 去。
