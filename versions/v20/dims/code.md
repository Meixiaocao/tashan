# `code` 类 · 专属取证

配合 `common.md` 的 G1–G7 使用。本文件只补代码类特有的两个维度与入口定位法。

## 先定位入口（G1 前置）

| 要找 | 怎么找 |
|---|---|
| 程序入口 | `main.py` / `manage.py` / `index.js` / `cmd/` / `package.json` 的 scripts |
| 请求入口 | 路由注册处（Flask `@app.route` / Express `router.*` / FastAPI 装饰器） |
| 页面入口 | `index.html` / `pages/` / 路由表 |
| 数据入口 | 连接配置、ORM 模型、SQL 目录 |

入口没找到 → 记"入口不可辨"，不得推测架构。

## A1 数据流与分层

- 入口到数据层是否单向；跨层调用点（页面直接拼 SQL、路由里写业务聚合）。
- 全局可变状态：单例、模块级缓存、全局连接未关闭。
- 配置、常量与业务逻辑是否分离；环境差异写死在代码里的处数。

**不合格形态**：页面文件里出现 SQL；工具函数反向 import 业务模块；同一配置在三处写死。

## A2 测试与校验

- 关键路径（登录 / 主查询 / 导出 / 支付类动作）是否有用例。
- 用例能否跑通：有测试命令就跑一次，记退出码与用例数。
- 有无可观察的失败态：故意改坏一处，看校验是否拦。**跑了才算有校验**。
- 覆盖率工具可用则记数值，不可用记"未测"。

## 代码类常见假象

| 假象 | 怎么破 |
|---|---|
| 目录分层看起来整齐 | 看 import 方向是否有环 |
| 有 verify 脚本 | 跑一次，看它输出的 PASS 是不是常量 |
| 有测试目录 | 看断言数与跳过数 |
| 有 README 架构图 | 与 import 图对照，不同则以 import 为准 |
