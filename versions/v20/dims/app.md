# `app` 类 · 专属取证

配合 `common.md` 的 G1–G7 使用。适用于可部署的运行体：服务、容器、常驻进程。

## B1 部署与运维

- 依赖版本：有无锁文件（package-lock / poetry.lock / requirements 固定版本 / go.sum）。
- 复装：从空目录到跑起来需要几步；有没有一键脚本；用到哪些未记录的隐式依赖。
- 配置：是否外置（env / config 文件）、是否区分环境、有无默认口令兜底。
- 运行：自启方式、日志去向与轮转、超时与并发上限、进程崩溃后由谁拉起。
- 数据：备份策略、恢复演练记录（有记录才算）。
- 回滚：上一个可用版本在哪、回滚命令是什么。

**合格证据**：compose 或 Dockerfile 行号、锁文件存在性、日志写入路径的代码行、缺回滚步骤的部署脚本行。

## B2 数据与口径

- schema 变更：迁移脚本目录 vs 手改；有无版本表。
- 索引：关键查询是否走索引（能连库就 EXPLAIN，不能连记"未验证"）。
- 时间：时区是否显式、跨日边界如何处理、时间戳有无单位歧义。
- 口径：指标定义与实现是否一致；同一指标在两个模块算法不同处数。
- 数据源：只读/读写分离；生产库与测试库的隔离手段。

**合格证据**：迁移目录与手改痕迹对照、EXPLAIN 输出、两处算法不一致的行号对。

## 应用类常见假象

| 假象 | 怎么破 |
|---|---|
| "一键部署" | 从空目录实跑一次，记录卡在第几步 |
| 有监控 | 看告警是否真的发出过（历史记录） |
| 有备份 | 问上次恢复演练日期，没有=无 |
| 多环境配置 | 看生产 env 里是否仍有调试开关 |
