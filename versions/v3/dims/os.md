# `os` 类 · 专属取证

配合 `common.md` 的 G1–G7 与"声明≠实现核查表"使用。适用于工作系统：规则集、流程、多文档协同体。

**这类对象最容易骗人**：它由文字构成，声明与实现长得很像。取证原则——**文字只是被审对象，不是依据**。

## D1 真相源唯一

1. 选 5 条关键结论（谁负责什么、什么时候做、标准是什么、数字是多少、边界在哪）。
2. 每条全盘搜关键词，记出现的文件数。
3. 逐字对比副本：是否已有漂移（改了 A 未改 B）。
4. 声明"唯一真相源"的文件，实际是否被其他文件复述或覆盖。
5. 索引层（目录页、入口页）指向的文件是否都存在；存在的是否还被维护。

**合格证据**：`grep` 命中的文件清单、两处文本的差异行、指向已删文件的链接行号。

## D2 闭环与分工

1. 每条硬性声明找兜底物：脚本、拦截器、校验命令、定时任务。找不到即"声明未落地"。
2. 一次完整动作（从触发到归档）是否真的产生写入：找一件真实案例，看落地产物。
3. 角色：谁判、谁做、谁复核；三者是否同一角色兼任（兼任处风险最高）。
4. 失效路径：规则被违反时会发生什么；有没有可观察的后果。无后果=软约束。
5. 时间尺度：规则多久被修订一次；有无过期条目仍在生效。

**合格证据**：兜底脚本路径 + 可运行记录、真实案例的写入文件、角色重合处的原文行号。

## 系统类常见假象

| 假象 | 怎么破 |
|---|---|
| "有机制保证" | 找脚本，跑一次；跑不通=无机制 |
| 文档很完整 | 抽样 5 条声明，逐条找兜底物 |
| 有流程图 | 拿一件历史案例对一遍，看流程是否真走过 |
| 有检查清单 | 看清单项最近一次被执行的时间 |
| 定期复盘 | 找复盘产出物；只有模板=没做过 |
