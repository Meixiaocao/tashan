## v25 · 2026-11-18 — F 接上真实判准度，并承认在原地打转

### F 改为纯乘法（f6）

```
F = 执行质量 × 判准度
执行质量 = min(1, 修复率) × (1−复发率) × 可信度
判准度   = 1 − 误报率，**自动从 objects/ledger.jsonl 的已复评批次读取**
```

判准度不再靠手工传 `--fp`——那个参数的分母是「上轮自评建议数」，与外部复核针对的「对外报告条数」不是一回事，接不上。现在直接从台账读，`0.817`（= 1 − 7.5/41）。

相乘而非相加：既要做对，又要判准，任一项为零则整体为零。

### 新发现：F 已经没有区分力

改完后 R17–R22 连续六轮同为 **0.8171**。原因：**执行质量几乎恒为 1**——我每轮都能把自己提的问题修完。于是 F 实际只等于精确率。

这是第三次碰到「指标饱和」，前两次是加法公式的基线分与满分封顶。

### 加存量指标 + STALL 判定

```
累计存量 = Σfound − Σfixed
```

```
R21 后：44 − 38 = 6（在涨）
R22 后：47 − 42 = 5（在涨）
```

**判定新增一档**：F 未降但存量在涨 → `STALL —— 修的速度赶不上发现的速度，在原地打转`。

当前判定就是 STALL。这是这套自评第一次给出负面结论——之前六轮全是 KEEP。

## v22 · 2026-11-18 — 革掉自己的分类法

**一句话**：删掉预置的认知框架，把顺序从「查表 → 对照」翻成「直觉 → 求证」。

### 为什么拆

v21 之前，铁律写着「标准不预置，每轮现搜」。但技能里同时躺着：

- 结果六类（找不到 / 看不懂 / 会做错 / 等太久 / 用不了 / 不敢信）
- 九维清单（G1–G7 + A/B/C/D）
- 依据四级（A 实证 / B 规范 / C 惯例 / D 偏好）

这三样不是内容标准，是**看世界的方式**。不预置内容而预置认知框架，等于说「除了我怎么看，别的都不预置」——与它判别人的第一条错误（声明有、接入无）同型。

更实际的代价：有框架就有检查表，有检查表就停止观察，只做勾选。18 轮里六类从未被质疑过一次。

### 新的三层

| 层 | 做什么 | 硬约束 |
|---|---|---|
| **空手看** | 不读文档、不读自述，直接看代码与产物，写怪处清单 | 不贴标签、不找依据、不联网 |
| **良知求证** | 每条过三关：说清 / 追源 / 可验 | 追不到但讲得出道理 → 标「推理」进表；讲不清 → 删 |
| **现场分组** | 按问题的共同性质分组，名字现场起 | 换个对象还用同组名 = 还在套模板 |

顺序是刻意颠倒的。旧流程「先查规范再对照」会让规范的边界变成视野的边界——规范没写到的东西，看不见。

## v19 · 2026-11-18 — 自检机制接上计算

自评 R15 抓到的硬 bug：`WEIGHTS` 常量与 `score()` 里的字面量是两条平行线——指纹取左边的哈希，算分用右边的数。改权重时自检报"无变化"，而口径实际已变。

- `score()` 改为从 `WEIGHTS` 取值，禁用字面量；权重只有一处定义。验证：`WEIGHTS["fix"]` 由 0.35 改 0.5，F 由 1.0 变 1.25。

这是本项目第 5 次同型错误：**声明有、接入无**。前四次在别的对象上，这次在自己的自检代码里。
