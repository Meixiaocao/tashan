# 优化分类与阶段评定

两层判据（结果六类、依据四级）回答“这条差距成不成立”。这一层回答“这条建议该不该无条件做，还是必须有人拍板”。

---

## 一、两类判别（Pareto 支配）

对每条建议，按固定六维逐维判「增 / 平 / 减」：

| 维度 | 看什么 |
|---|---|
| 耗时 | 首屏加载、接口响应、操作等待 |
| 感知密度 | 一屏可见信息量、完成一件事的步数 |
| 服务器资源 | CPU、内存、磁盘、带宽 |
| 暴露面 | 可被无凭证访问的入口数、可触达的数据范围 |
| 可维护性 | 改动半径、定位成本、可测性 |
| 交付成本 | 本次需要的人力与时间（只记在哪一维付出，不估数） |

判定：

| 结果 | 类型 | 处理 |
|---|---|---|
| 六维中无一项变差，至少一项变好 | **支配型** | 无条件做，进主表 |
| 有一项或以上变差 | **权衡点** | 单列，写“需裁决”，不进必做清单 |
| 六维全平 | 无收益 | 删除 |

**支配型不需要讨论，权衡点不需要争论对错**——前者是算法结论，后者是价值判断。

---

## 二、约束清单（“现有条件”必须写成条目）

“现有条件下最优”若没有这张表，就等于“我觉得最优”。评审可以向对象要这张表，但要的是**决定**，不是自述。

| 约束 | 值 | 谁给 |
|---|---|---|
| 人力与时间窗 | | 决策者 |
| 部署形态 | 单机 / 多机 / 有无反向代理 | 决策者 |
| 资源上限 | CPU / 内存 / 带宽 / 磁盘 | 决策者 |
| 不可动接口 | 已联调、已上线的 | 决策者 |
| 团队能力边界 | 能否维护拆分后的结构 | 决策者 |
| 演示或交付期限 | 日期 | 决策者 |

缺这张表时，报告只能出阶段 A；阶段 B 标「待约束」，不得替决策者假设。

---

## 三、两阶段评定

| 阶段 | 内容 | 谁定 | 产出形态 |
|---|---|---|---|
| **A 无条件区** | 支配型，按影响大小排序 | 评审者可判 | 有序清单 |
| **B 权衡区** | 前沿点，逐点列代价 | 决策者定权重 | 矩阵，不给总分 |

矩阵只列代价，**不做加权求和、不排序**。加权求和会把隐式权重糊进一个数字，让冲突消失——而那正是要被看见的东西。

---

## 四、停止线（satisficing）

不设“全部修完”，设 3–6 条可测的期望水平。**达到即停**，剩余转「已知取舍」并记录理由。

| 期望水平 | 取法 |
|---|---|
| 首屏传输 ≤ N KB | 按网络条件定，写明 gzip 前后 |
| 无凭证可达入口 = 0 | 硬性 |
| 最大单文件 ≤ N 行 | 按团队可读性定 |
| 零测试组件 = 0 | 硬性 |
| 审计留痕 > 0 行 | 硬性 |
| 关键异步操作有加载态 | 按操作清单核 |

期望水平由决策者定，评审只提供当前实测值。

---

## 五、职责边界

- 评审**画前沿，不选点**。选点需要权重，权重不在评审手里。
- 权衡点**不是风险，不是缺陷**。它是已承认的属性冲突（ATAM 的 tradeoff point 定义），写进报告但不计入 `found`。
- “资源不够”是**约束变化**，不是差距。约束变了就重算前沿，不是加一条缺陷。

---

## 六、理论出处

| 概念 | 出处 | 借用什么 |
|---|---|---|
| Trade study | NASA SEH 4.0 系统设计过程｜INCOSE 9.6.2 Standard Approach to Trade Studies | “现有条件下最优”= 约束 + 候选 + 评价，不是单点最优 |
| Pareto 支配 / 前沿 | 多目标优化 | 两类判别的算法；前沿点之间无优劣 |
| tradeoff point | ATAM（SEI, 2000） | 同时服务一个质量属性并损害另一个的决策；且明确“tradeoff point 不是 risk” |
| satisficing | Simon, 1955（有限理性） | 不追最优，设期望水平，达到即停 |

---

## 七、常见误用

| 误用 | 后果 |
|---|---|
| 把权衡点写进必做清单 | 制造假优先级，决策者被迫在没看到代价时点头 |
| 用加权总分给前沿点排序 | 权重隐式化，冲突被一个数字掩盖 |
| 约束缺省还宣称“最优” | “现有条件下”退化成主观判断 |
| 把资源不足写成缺陷 | 治不了：那是约束，要么扩容要么降期望 |
| 所有条目都判支配型 | 说明六维没逐维过，只是在给建议找理由 |
