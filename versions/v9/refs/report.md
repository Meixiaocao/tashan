# 报告规范

## 一、落盘（不与被审对象同置）

报告写在**对象同级**目录，避免成为下一轮评审的材料：

```
<对象父目录>/评审-<对象名>/他山-<维度>-<YYYYMMDD>.md
```

父目录不可写 → 退到对象内 `评审/`，头注"退路落盘，下轮评审须排除本文件"。
全部不可写 → 直接输出到对话，头注"未落盘：原因"。

原文独立成文，事后不改一字；批注写在自己文件里。

## 二、骨架

```
# 他山评审 · <对象> · <维度> · <YYYY-MM-DD>
头注：对象类 / 维度 / 输入路径 / 证据来源 / 取证时点 + 工作区状态（已提交／未提交） /
      历史参照：无 / 默认与残留 / 自评局限 / 引用约定 /
      本轮计数：found=<N> new=<N> carried=<N> recur=<N>

1 现实清单    | # | 事实 | 位置 |
2 参照源      | # | 来源 | 内容年份 | 口径 | 结果 | 依据 | 为何可比 |
3 差距表      | # | 场景句式 | 结果 | 证据 | 影响面 | 偏离度 |
4 建议        | # | 对应差距 | 改法 | 验后值（命令） | 依据 |
5 未查范围    | 项 | 原因 |
6 自检        <逐条打勾>
```

**取证时点是硬要求**。对象正在被并行修改时，头注写工作区状态（已提交／未提交），且 D2 只能引用复跑值，不得引用旧快照。

**偏离度四档**：违背硬标准 ｜ 落后通行做法 ｜ 另一种选择 ｜ **待拍板（产品决定）**。
最后一档指账号权限、部署归属、演示形态这类已定方向但未实施的事项：写进主表但**不计入修复优先级**，也不计进 `found` 的硬缺陷部分。

**非缺陷单列，不进主表**。对象做对的地方另起小表；混进主表会抬总条数、稀释优先级，属于失真。

**条数不设下限**：由证据决定，健康对象出 2 条是正确的输出。但 `found` 低于上轮一半时，须在第 5 节说明是"确实修好了"还是"这次没查透"。

**三个计数必须分开记**（喂给 `evolve.py record`）：

| 计数 | 含义 |
|---|---|
| `new` | 本轮首次发现 |
| `carried` | 上轮已列、本轮仍在 |
| `recur` | 与上轮**同根因**的新形态（换了马甲） |

## 三、写作口径

- 只写“当前是什么、参照是什么、差多少”，不写“应该重视”。
- 一条差距只讲一件事；两件事拆两条。
- **结果**列写六类之一（找不到 / 看不懂 / 会做错 / 等太久 / 用不了 / 不敢信），写不出的不进主表。
- **依据**写 A/B/C/D：实证 / 规范 / 惯例 / 偏好；D 级不进主表。
- 阈值必须带口径（gzip 还是原始、JS 还是全部资源、第几百分位）；口径缺失的数不得用。
- **验后值**写“改成什么、用哪个命令量得到”，下一轮照它判，不重跑。
- 不用“显著/大幅/极大”这类无度量的词。
- 引用对象原文术语时加「」标注，避免被同一套词带走。
- 脚本命中一律标“启发式，需确认”，命中不等于结论。

## 四、每条差距的自检

1. 触发条件写具体了吗（"某人点某按钮"而非"在交互时"）？
2. 证据能按图索骥吗（行号打开即是 / URL 打开即是）？
3. 参照度量能算出差值吗？算不出→降为“另一种选择”，不占主表。
4. 这条会不会下轮以同根因换形态回来？会的话，根因写进建议，不只写现象。
5. **结果**能落到六类中的哪一类？落不进→移入“另一种选择”或删除。
