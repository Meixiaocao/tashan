# G0 架构对标（agent 类首跑）

隔离与对标**能力组件层**：这个系统由哪些子系统构成、缺哪个、哪个是多余的、内核是否该换。

不判文件怎么放（G5）、不判数据怎么流（A1）、不判代码怎么写（G1–G7）。

---

## 一、为什么最先跑

架构层缺件时，下层评审失去意义。缺状态持久化，拆文件解决不了"任务中断要重跑"；缺审批点，补按钮解决不了"高危动作无人确认"。

先出能力矩阵，再决定下面各维要不要跑、跑哪几维。

---

## 二、十个子系统（标尺）

来源：arXiv 2609.00006 对 11 个 coding agent 的源码级研究（子系统 × 最小形态 × 最大形态）、aiarch.dev 的分层模型、OpenAI Sandbox 文档、AWS agent reference architecture。

| # | 子系统 | 最小形态（缺了会怎样） | 成熟形态 | 怎么查 |
|---|---|---|---|---|
| 1 | 推理循环 | 一个循环套一个工具；失败即停 | 停止条件、最大步数、失败恢复、可中断 | 找主循环与停止判据 |
| 2 | 上下文管理 | 全量重放，长任务变慢变贵 | 压缩历史、延迟加载工具定义、卸载超大工具返回 | 搜 compact / summarize / truncate / 延迟注册 |
| 3 | 工具层 | 一个万能入口 | schema 校验、超时、权限分级 | 工具注册处与参数校验 |
| 4 | 沙盒 | 直接跑在宿主上 | 隔离执行环境（文件系统 / shell / 快照），或把沙盒当工具调用而非常驻 | 找进程启动方式、挂载、容器 |
| 5 | 记忆 | 只有会话内历史 | 短期 / 长期分层，可检索、可写入 | 搜 memory / 长期存储 / 检索 |
| 6 | 状态持久化 | 重启即丢 | 断点续跑、崩溃恢复、中断可续 | 搜 resume / checkpoint / durable / recover |
| 7 | 编排 | 单 agent 串行 | 子 agent、任务分解、并发上限 | 找派生子任务与并发控制 |
| 8 | 可观测 | stdout 日志 | trace：做了什么、看到什么、花了多少、为什么停 | 搜 trace / span / cost / token 计量 |
| 9 | 评估 | 无回归集 | 固定任务集 → 发布门禁 | 找 eval 集与判定脚本 |
| 10 | 审批与边界 | 无 | 人工审批点、凭证作用域、出口策略 | 搜 approval / confirm / egress / scope |

## 三、四档判定

| 档 | 判据 | 记法 |
|---|---|---|
| **有** | 找到实现且能指出入口 | ✅ |
| **部分** | 有雏形但覆盖不全，能说出缺哪一段 | ◐ |
| **无** | 反向词表搜过仍无实现 | ✗ |
| **不需要** | 能写出"缺了会怎样"且能说明这套场景下为何不成立 | — |

**"不需要"必须写两句**：缺了会发生什么、为什么这里不成立。少一句就退回"无"。
例：只读工具型 agent 不必要独立沙盒，因为它不执行模型生成的代码——**前提是没有代码执行入口**，有了前提就变。

## 四、内核选型判定（是否过时）

七维逐个判，不靠印象：

| 维 | 看什么 | 落后表现 |
|---|---|---|
| 模型支持 | 单厂商 / 多 provider / 本地 | 只能接一家，换模型要改代码 |
| 上下文效率 | 压缩、延迟加载工具、卸载大返回 | 每轮全量重放，成本随轮次线性涨 |
| 子 agent | 能否派生独立上下文的子任务 | 只能单线程做，长任务无法拆分 |
| 沙盒形态 | 整会话隔离 / 工具级 / 无 | 无隔离却允许执行生成代码 |
| 状态持久化 | 断点续跑、崩溃恢复 | 中断即重来 |
| 扩展面 | MCP / skills / 自定义工具注册 | 加一个工具要改内核 |
| 可观测 | trace 与成本计量 | 只知道输出，不知道过程 |

**判定门槛**：三项以上落后，且每一项都能追到结果影响（等太久 / 会做错 / 不敢信），才算"过时"。
不足三项 → 记"保守"，进权衡点，不算缺陷。

不推荐具体替代品——选型是决策者的活。

## 五、防误报（本维误报率最高）

架构能力最容易被**命名**误导。断言"没有 X"之前，必须搜过反义与替代实现：

| 断言 | 必搜 |
|---|---|
| 无记忆 | memory / history / context / compact / summarize / session / 长期存储 |
| 无持久化 | resume / checkpoint / durable / recover / restore / 续跑 |
| 无沙盒 | container / isolation / jail / workspace / mount / 进程启动方式 |
| 无可观测 | trace / span / log / metric / telemetry / token 计量 |
| 无审批 | approval / confirm / interrupt / human-in-the-loop / 权限分级 |
| 无编排 | subagent / task / spawn / queue / 并发上限 |

**依赖包也是实现**。能力可能来自 npm / pip 依赖（如 `pi-durable` 提供持久化），不在源码里。
判定前先读 `package.json` / `requirements.txt`，把依赖算进"有"。

**目录名不等于能力**。`engine/pi/` 里有 18 个文件，不等于它就是内核——可能是自建工具集，内核在依赖里。

## 六、输出形态

```
## 能力矩阵
| # | 子系统 | 现状 | 参照 | 差距 | 结果类 | 判定 |

## 三条结论
1. 缺什么（按结果影响排序，不按清单顺序）
2. 什么可以不要（给理由与前提）
3. 内核是否该换（按七维，够门槛才写"过时"）

## 前置前提
这套判定成立的前提：允许模型执行生成的代码 / 需要跨会话续跑 / 有多任务并发。
前提不成立时，对应项从"缺"降为"不需要"。
```

## 七、与其它维的边界

| 维 | 判的是 | 例 |
|---|---|---|
| **G0** | 有哪些子系统、缺哪个 | 缺人工审批点 |
| G5 结构 | 文件与模块怎么放 | store 文件 2078 行 |
| A1 数据流 | 数据怎么流、层间依赖 | engine 直接 import 上层 |
| G3 可靠 | 运行时行为 | 并发满直接拒绝 |

同一件事只能落在一条维里。G0 说"缺持久化"、G5 说"store 太大"是两件事；若 G5 的结论其实是持久化缺失导致的，写到 G0 去。
