## 一、外部标尺表

引用时写清条款或数值，不写"业界普遍认为"。

| 类别 | 标尺 | 具体值 / 条款 | 来源 |
|---|---|---|---|
| 性能 | Core Web Vitals 良好阈值 | LCP ≤ 2.5s ｜ INP ≤ 200ms ｜ CLS ≤ 0.1（第 75 百分位） | web.dev/vitals |
| 性能 | 首屏 JS 预算 | 约 170KB gzip 为常见上限 | web.dev "The cost of JavaScript" |
| 渲染 | 长列表阈值 | 可视节点 > 200 行建议虚拟化 | react-window / TanStack Virtual 文档 |
| 交互 | 正文对比度 | ≥ 4.5:1（大文本 ≥ 3:1） | WCAG 2.2 SC 1.4.3 |
| 交互 | 触控目标 | ≥ 24×24 CSS px（AA）；44×44 为移动端惯例 | WCAG 2.2 SC 2.5.8 / Apple HIG |
| 交互 | 焦点可见 | 键盘焦点必须有可见指示 | WCAG 2.2 SC 2.4.7 / 2.4.11 |
| 交互 | 可用性启发式 | 10 条（状态可见/贴合现实/可控/一致/防错/识别优于回忆/效率/简洁/错误恢复/帮助） | Nielsen Norman Group |
| 交互 | 中后台表格密度 | 行高 40–48px，首屏 15–20 行 | Ant Design Pro 表格密度规范 |
| 质量 | 产品九特性 | 功能适合/性能效率/兼容/交互可用/可靠/安全/可维护/可移植 | ISO/IEC 25010:2023 |
| 架构 | 质量属性 + 场景六要素 | 性能/可用/安全/可修改/互操作；刺激源-刺激-环境-制品-响应-度量 | ATAM（SEI） |
| 交付 | 四项核心指标 | 变更前置时间/部署频率/变更失败率/恢复时长 | DORA |
| 技能 | 四评估维 | 安全/质量（有无增益）/可靠（触发精度）/成本效率 | skill 评估实践（Anthropic、AWS 样例） |
| 文档 | 审计维度 | 覆盖/可查找/准确/时新/结构/可及 | 知识库与文档审计实践 |
| 文档 | 可信判据 | 标了"唯一真相源"不等于可信，须验证副本数 | SSOT 审计实践 |

阈值随版本变化，采用时记抓取日期。

## 二、参照源路由

每类至少 3 条，优先取"有实现细节"的源，弃榜单与厂商自评。

| 类 | 搜什么 | 达到可比的条件 |
|---|---|---|
| `code` | 同域开源项目的目录结构/选型说明；框架官方最佳实践；该领域权威清单（awesome-x） | 规模同量级、问题域同型、有代码可看 |
| `app` | 同类工具的公开文档与操作说明；部署运维实践 | 使用者角色相同，非消费级产品 |
| `skill` | 技能市场同类件的结构；官方技能编写指南；技能评估研究 | 触发场景重叠或任务同型 |
| `os` | 工程效能框架（DORA/SPACE）；知识审计/SSOT 审计方法 | 团队规模同量级，不搬大厂流程 |

**可比性三问**（任一答不出即弃用）：做的是一类事吗？规模差几倍？结论有实现细节支撑吗？

## 三、报告模板

```markdown
# 他山评审 · <对象> · <维度> · <YYYY-MM-DD>

- 对象类：<code|app|skill|os>
- 审的维度：<代号 名称>
- 输入路径：<绝对路径>
- 历史参照：无（本次独立生成）
- 自评局限：<若评审者与对象同源则写，否则删此行>

## 1 现实清单
| # | 事实 | 位置 |
|---|---|---|

## 2 参照源
| # | 来源 | 抓取日期 | 为何可比 |
|---|---|---|---|

## 3 差距表
| # | 场景句式 | 证据 | 影响面 | 偏离度 |
|---|---|---|---|---|

## 4 建议
| # | 对应差距 | 改法 | 依据 |
|---|---|---|---|

## 5 未查范围
| 项 | 原因 |

## 6 自检
- [ ] 零内部术语
- [ ] 未引用自我介绍类文件作依据
- [ ] 每条差距有 文件:行 或 URL
- [ ] 无工作量估算
- [ ] 无历史报告引用
- [ ] 盲区已列
```

**条目数**：主表 8–15 条。少于 8 条须在第 5 节说明为何少（题材小 / 证据不足），不得凑数。

## 四、写作口径

- 只写"当前是什么、参照是什么、差多少"，不写"应该重视"。
- 一条差距只讲一件事；两件事拆两条。
- 排序按 影响面 × 偏离度，同级按证据确定度。
- 建议必须能由一个具体动作落地（改哪里、改成什么），不写"优化一下"。
- 全文不用"显著/大幅/极大"这类无度量的词。
