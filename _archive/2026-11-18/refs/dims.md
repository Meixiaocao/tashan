# 维度清单（取证用）

选好类与维后再读本文件，只读对应小节。

---

## 第一部分 · 对象识别信号

满 2 条即判为该类；多类同时满足时取主类。

| 类 | 信号 |
|---|---|
| `code` | 源码目录；依赖清单（package.json / requirements.txt / go.mod）；构建或测试配置；无部署编排 |
| `app` | Dockerfile 或 compose；有常驻服务定义；数据库 schema/迁移；环境变量配置 |
| `skill` | SKILL.md 且含 description 触发描述；被某 agent 加载 |
| `os` | 同一事实在 ≥2 个文件出现；明文执行契约或流程；有"谁判/谁做"的分工表述；有写回或交接动作 |

识别只看物理事实，不认自称（"我们是平台"不算 app 信号）。

## 第二部分 · 通用 7 维

### G1 有效性 — 声称解决的问题真解决了

**取证**：
1. 找到入口（main / 路由表 / 首页）→ 走一遍主线。
2. 真实性：mock、硬编码样例、示例数据在真实路径上的占比。
3. 功能缺口：对照同类产品的标准功能清单，缺哪些。
4. 空壳率：有 UI 无后端、有后端无数据源的模块数。

**合格证据**：`文件:行` 的硬编码值、缺 handler 的路由、返回固定值的函数。

### G2 效率 — 响应、资源、运行成本

**取证**：
1. 静态体积：首屏 JS/CSS 总量（gzip 后）、单文件最大体积、图片格式。
2. 请求模式：循环内 IO、N+1 查询、无索引查询、全表扫、可并行却串行的调用。
3. 渲染：长列表是否虚拟化、无谓重渲染触发点、阻塞首屏的同步脚本。
4. 运行成本：单次任务 token/算力/外部 API 调用次数（AI 类必查）。
5. 依赖重量：装上但只用一两个函数的库。

**合格证据**：文件字节数、`文件:行` 的循环内查询、依赖清单里的大库 + 调用点。

### G3 可靠 — 失败模式与恢复

**取证**：
1. 错误处理：裸 except / 空 catch 比例；错误是否被吞。
2. 边界：超时、重试、并发上限、队列满。
3. 状态可见：失败后操作者看到什么；有无错误态。
4. 可观测：日志级别、请求 ID、健康检查端点。
5. 恢复：进程重启后数据一致性；有状态服务是否持久化。

**合格证据**：`文件:行` 的 `except: pass`、无 timeout 的请求、缺错误分支的 switch。

### G4 安全 — 权限、秘密、注入面

**取证**：
1. 秘密：仓库内硬编码的密码/密钥/连接串（含注释与示例文件）。
2. 注入：字符串拼接 SQL、命令拼接、模板注入。
3. 认证授权：未鉴权端点清单；权限检查是否集中。
4. 暴露面：`*` CORS、调试端点、目录列举、默认口令。
5. 依赖漏洞：能跑就跑审计命令，不能跑记"未验证"。

**合格证据**：`文件:行` 的秘密字面量、拼接语句、无鉴权判断的路由。

### G5 结构 — 耦合、边界、理解成本

**取证**：
1. 体积分布：文件行数排序；最大文件承担了几种职责。
2. 依赖方向：是否有环；下层是否反向依赖上层。
3. 重复：同一逻辑多处实现（复制粘贴型补丁）。
4. 命名与目录：目录名声称的职责与实际内容是否一致。
5. 配置与代码：可变参数是否外置。

**合格证据**：最大文件行数 + 职责列举、环路路径、重复块的行号对。

### G6 交互 — 层级、密度、一致性、可达性

**取证**（逐页，不得抽样后宣称全覆盖）：
1. 层级：首屏第一眼看到什么；主要动作是否在首屏。
2. 密度：表格首屏可视行数；关键信息是否要滚动三屏才见。
3. 一致性：同功控件是否两种实现（按钮/日期/分页）。
4. 键盘：Tab 顺序、焦点可见、Esc 关闭、Enter 提交。
5. 对比度：正文与背景比值；触控目标尺寸。
6. 三态：空态、加载态、错误态是否都有。
7. 响应式：窄屏是否横向滚动、是否重排。

**合格证据**：页面 DOM 行号、断点与对比度数值的 CSS 行、缺三态的选择器。

### G7 互操作 — 契约与兼容

**取证**：
1. 字段命名：同一接口内 snake/camel 混用情况。
2. 时间与单位：时区、格式、单位是否显式。
3. 错误码：是否统一、能否判定含义。
4. 版本：接口版本策略、破坏性变更记录。
5. 兼容：与上下游既有约定的偏离点。

**合格证据**：两处字段命名的行号对、无时区的时间戳、错误码散落点。

## 第三部分 · 专属 2 维

### `code`

**A1 数据流与分层**
- 入口到数据层是否单向；跨层调用点。
- 全局可变状态（单例、模块级缓存）数量。
- 配置、常量与业务逻辑是否分离。

**A2 测试与验收闸**
- 关键路径（登录 / 主查询 / 导出）是否有用例。
- 用例是否可跑通、是否有可观察的失败态。
- 是否真有闸门在拦（跑一次看它拦不拦）。**写了不算**。

### `app`

**B1 部署与运维**
- 依赖版本是否锁定；能否一键复装。
- 配置是否外置、是否区分环境。
- 自启、日志轮转、备份、回滚路径。

**B2 数据与口径**
- schema 变更方式（迁移脚本还是手改）。
- 关键查询的索引覆盖。
- 时区与时间边界；口径定义与实现是否一致。

### `skill`

**C1 触发精度**
- description 触发词覆盖度（应加载的说法 / 不应加载的近似说法）。
- 与相邻技能的触发词重叠区。
- 自动触发还是需点名；误触发代价。

**C2 载荷与冲突**
- 主文件行数/字节数；一次加载占多少上下文。
- 引用文件是否按需加载（还是等于全读）。
- 指令是否与宿主纪律矛盾（矛盾处必列）。
- 是否有可判定的出口（完成长什么样、失败怎么办）。

### `os`

**D1 真相源唯一**
- 同一事实出现在几个文件（全盘搜关键结论句）。
- 副本是否已漂移（逐字对比）。
- 声明"唯一"的文件与实际占用者是否一致。

**D2 闭环与分工**
- 每条声明对应哪个脚本/闸门在兜底。
- 一次完整动作是否发生写回。
- 谁判、谁做、谁复核，是否同一角色兼任。

## 第四部分 · 取证纪律

- 每维至少 **5 条事实** 才允许下"健康/不健康"判断；不足 5 条只能写"证据不足"。
- 只记形态与位置，不记形容词。
- 盲区（读不到、跑不起、无权限）必须在报告第 5 节列出，不得用推断填坑。
