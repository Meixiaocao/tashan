# 校准库 · 误报样本

存的是**已经发生过的误判**。每轮评审开头读当前对象的样本（取 5 条），同一模式不重犯。

存在的理由：他山的五类误报全部出于同一个模式——拿静态存在性证明行为性结论。样本把这条教训变成可检索的清单，而不是靠记忆。

## 文件命名

```
calibration/<对象名>-<YYYYMMDD>.jsonl
```

例：`数搭前端-20261118.jsonl`

- 一个对象一个文件，不混；S1 只读当前对象的文件。
- 同一对象不同日期的采集分文件，读取时按日期倒序取最近 5 条。

## 一条样本

```json
{"id":"FP-G6-07","object":"前端原型","dimension":"G6","claim":"4个输入无标签","verdict":"false_positive","why":"动态 input 在 label.field 内，浏览器可得到可访问名称","lesson":"标签检查看 DOM 包裹与可访问名称，不只看 aria-label 计数","assert_type":"可达性"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `<verdict 缩写>-<维度>-<序号>` |
| `object` | 是 | 被审对象，与文件名一致 |
| `dimension` | 是 | G0–G7 / A / B / C / D |
| `claim` | 是 | 当时的断言原文 |
| `verdict` | 是 | 见下表 |
| `why` | 是 | 为什么判成这样，带文件位置 |
| `lesson` | 是 | 下次怎么避免，一句话，可执行 |
| `assert_type` | 是 | 断言类型，用于检索 |

## verdict 取值

| 值 | 含义 |
|---|---|
| `false_positive` | 完全判错 |
| `partial` | 部分成立，范围或口径有误 |
| `true_positive` | 判对，且修复后验证过 |
| `stale_snapshot` | 判对但数据已过期（并行修复期常见） |
| `unit_mismatch` | 数值对但口径错（如未压缩比 gzip） |
| `product_decision` | 是产品决定，不该当缺陷 |
| `gap_in_skill` | 暴露的是评审流程的漏洞 |

后三种不进对象的收敛率统计，进他山自己的账。

## assert_type 取值

按 `dims/common.md` §四的匹配表：`行为` / `配置` / `依赖` / `版本控制` / `可达性` / `状态标识` / `数量` / `流程` / `口径`。

检索时按本轮维度的相关类型过滤，不要全读。

## 怎么加一条

1. 只记**已经由外部复核确认**的判定，自己怀疑的不记。
2. `lesson` 写成可执行的检查动作，不写"要注意"。
3. 加完检查 JSON 语法：`python -c "import json;[json.loads(l) for l in open('文件')]"`

## 怎么用

在 `SKILL.md §3 S1` 第 0 步：读当前对象的样本，按 `assert_type` 挑相关的最多 5 条。对象没有样本就跳过，不读别人的。

**库再大，读取量恒定**——这是设计约束，别为了"全面"把整库塞进上下文。

## 对象类型覆盖

每类对象至少留 1 份样本；缺的明写缺口，不假装覆盖。

| 类 | 样本 | 状态 |
|---|---|---|
| `app` 应用/前端 | `数搭前端-20261118.jsonl`（13 条） | 有 |
| `code` 代码库 | — | **缺** |
| `os` 系统/运行时 | — | **缺** |
| `skill` 技能 | 自评 18 轮（未转样本） | 部分 |
| `arch` 架构对标 | `refs/samples/agent-arch-20261118.md`（是采样不是误报样本） | **缺** |

缺口原因：样本只能来自真实交付后的外部复核，不能造。审到新类对象、且对方给了复核，就补一份。
